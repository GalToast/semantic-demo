Phase 3a (navStore mirror) regression + amend-recovery lessons (2026-06-25).

LESSON 1 — Don't `git commit --amend` when parallel sessions may have committed since your last commit. I committed 00dba4ef, then parallel session's 191ffe4a and d1b28342 landed. I tried `git commit --amend` to fix a regression, but HEAD was the parallel session's commit, not mine. My amend silently rewrote their commit, splicing my navigation.svelte.ts fix into it. Recovered via `git reset --soft d1b28342` then fresh commit. Master ended clean (parallel session's commit preserved + my fix as 49088313).

Rule: BEFORE `git commit --amend`, always run `git log -1 --oneline` to verify HEAD is YOUR last commit. If not, use `git commit` (new commit) instead.

Dual-state-mirror Phase 3 architectural finding (2026-06-25): navStore and appState.navState are INTENTIONALLY separate sources of truth. They CANNOT be merged.

navStore = runtime source for components (Svelte 5 writable, sync, reactive). appState.navState = global/legacy source for window.__APP_STATE__ compat. W11-T4 readLegacyNavField contract requires appState to be PARTIAL with a fallback chain (window.__APP_STATE__ / __TEST_STATE__ / __semanticState / window.state).

The contract tests (state-class-migration-5-navigation.test.ts) do: set appState.mode = search, call navStore.set with mode='', expect currentMode() returns search (via fallback). If navStore.set pushes to appState, the fallback never fires.

Phase 3a (mirror via $effect.root() for external writers) is the right boundary. Phase 3b/c/d as originally planned (delete navStore, migrate readers) is NOT viable without breaking the W11-T4 contract.

Lesson: read CONTRACT tests for invariants BEFORE refactoring. State-class-migration-5-navigation.test.ts is the contract test that documents the dual-state invariant.

Lessons captured (2026-06-25): (1) Always run test:unit TWICE with git status between — initial verification can be false positive from test isolation. (2) Read contract tests for invariant before refactoring. (3) Subagents benefit from explicit DRIFT REPORTING — they may discover architectural issues that need user-level input. <!-- created=2026-06-26, last=2026-06-26 -->
