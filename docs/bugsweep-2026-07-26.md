## Provider capacity limits

Discovered through overload cascades:

| Lane             | Safe concurrent limit  | What happened at overload                                                           |
| ---------------- | ---------------------- | ----------------------------------------------------------------------------------- |
| **opencode-zen** | ~3-4 workers           | 8 workers → stores stuck at 192B for 600s (timed out), search-retry silent 5+ min   |
| **mistral**      | ~1-2 workers           | 3 workers → all silent 5+ min, very slow cold-start                                 |
| **logfare**      | 1 worker               | 2nd worker → connection error                                                       |
| **nvidia**       | 1 fast model at a time | Thinking models → 429 rate-limit; fast models (poolside) work but need 600s timeout |

### Optimal swarm configuration

- **3-4 workers max** across different provider lanes
- **Primary bugsweep models**: `mimo-v2.5-free` + `deepseek-v4-flash-free` (both EXCELLENT)
- **Secondary**: `nemotron-3-ultra-free` (reliable but needs lane headroom)
- **Spread across lanes**: don't put more than 3-4 on opencode-zen, 1-2 on mistral, 1 on logfare, 1 on nvidia
- **Prompt instruction**: add "Be CONCISE — do not generate excessive reasoning. Write the report directly." for thinking-heavy models
- **Timeout**: 600s minimum for multi-file bugsweep (300s only for single-file probes)

## Key findings from completed reports

### Keyboard module (`mimo-v2.5-free`, 15 findings: 4 HIGH + 7 MED + 4 LOW)

**HIGH findings:**

1. **H-1**: `focus-trap.ts:22-23` — Global singleton trap state with no multi-caller safety. Module-level `let activeTrapContainers: string[] = []; let isTrapping = false;` means nested traps (dialog + overlay) overwrite each other. Second caller's `setupFocusTrap()` silently abandons the first caller's container. **Fix**: Replace singleton with a stack/ID-keyed registry.

2. **H-2**: `focus-trap.ts:47-88` — Missing `e.isComposing` guard in `handleKeydown`. When IME composition (CJK input) is active and Tab is pressed, the trap intercepts the keystroke and forces focus, disrupting composition. Same class of bug fixed in `global-shortcuts.ts:65` and `keyboard-help.ts:45,284` but NOT in focus-trap. **Fix**: Add `if (e.isComposing) return;` as first line of `handleKeydown`.

3. **H-3**: `keyboard-help.ts:35-36` — Module-level mutable singleton ownership variables. Same pattern as H-1 — global state that can't handle multiple concurrent callers.

4. **H-4**: (see full report at `tmp/bugsweep/keyboard/REPORT.md`)

**MED findings**: 7 (see full report)
**LOW findings**: 4 (see full report)

### Utils module (`deepseek-v4-flash-free`, 37 files audited)

**HIGH findings:**

1. **H1**: `camera-math-utils.ts:28-29` — Unsafe non-null assertion `framing.travelVector!.clone()` on optional field. `FramingParams.travelVector` is declared `travelVector?: Vector3` (optional), but the `!` assertion bypasses the type system. If called without `travelVector`, throws `TypeError: Cannot read properties of undefined (reading 'clone')`. **Fix**: Either make `travelVector` required, or guard with `framing.travelVector?.clone() ?? new Vector3()`.

2. **H2**: `disposable.svelte.ts` — Does not auto-dispose despite claiming to. Memory leak risk / misleading contract. (see full report for details)

## Zombie-field scan discipline (2026-08-06, main-lane lesson)

When sweeping for "zombie" state mirrors (fields/decls with 0 runtime readers, like the removed `appState.searchSummary` in 4afb5dc1), **include TEST-SOURCE references as legitimate readers** — a runtime-prod-reader-only scan false-positives on contract-pinned state.

Example: `appState.pointsMaterial` + `appState.nodeSporeMaterial` looked 0-reader, but `tests/unit-active/state-three-handles-typing-contract.test.ts` + `state-three-handles-batch2-typing-contract.test.ts` SOURCE-MATCH app.svelte.ts for those imports + `$state` decls + `syncPointsHandles` writes (same-object-reference assertion). They are the documented **Tier-D engine-boundary state contract** — removal was reverted, NOT-A-BUG.

**Rule**: before removing any mirror/field, `rg` for test-source consumers too, not just runtime prod readers. A real zombie (like searchSummary) has NO test pinning it; a contract-pinned surface does. Verify via test-suite greens before/after, not just a reader scan. (Lessons also logged in switchboard task #7 resolution.)
