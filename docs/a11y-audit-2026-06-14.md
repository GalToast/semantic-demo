## 1. Scope

This is a focused a11y audit of the Svelte UI chrome — the DOM layer that wraps the Three.js 3D canvas. Out of scope: engine kernel (`js/modules/*`), 3D canvas internal a11y (no DOM), full WCAG AA conformance, the 11 M3 UI/UX tickets.

**Goal:** Find 5–10 high-leverage a11y tickets. Focus on keyboard navigation, ARIA landmarks, focus management, screen reader support, and semantic HTML.

## 3. Audit Findings

### A2-1: Broken skip link target — `#main-content` does not exist

**Severity:** HIGH
**WCAG:** 2.4.1 Bypass Blocks (Level A)
**File scope:** `src/App.svelte`, `src/index.html`

**Root cause:** The skip link (`<a href="#main-content">`) targets an element ID that doesn't exist anywhere in the Svelte app. When activated, focus stays on the `<a>` element — the user gets no benefit.

**Evidence:**
```
Skip link: <a href="#main-content" class="skip-link">Skip to main content</a>
document.getElementById('main-content') → null
After Enter: activeElement = <A> (the skip link itself), url = #main-content
```

**Recommended fix:**
Wrap the primary content area in `<main id="main-content">` inside `App.svelte`. The `<main>` element should contain the Canvas, Legend, Search, InfoPanel, and all interactive UI — everything except the skip link itself and the loading overlay.

**Verification:** After fix, pressing Tab → Enter on skip link should move focus to the first interactive element inside `<main>`.

---

### A2-2: No `<main>` landmark

**Severity:** HIGH
**WCAG:** 1.3.1 Info and Relationships (Level A), 2.4.1 Bypass Blocks
**File scope:** `src/App.svelte`

**Root cause:** The document has no `<main>` element. Screen reader users cannot jump to primary content using landmark navigation. The existing landmarks are:
- `banner` (header — good)
- `complementary` × 2 (legend, info panel — good)
- `search` (search bar — good)
- `toolbar` (camera controls — good)
- `application` (canvas — good)
- `list` (focus pocket a11y — good)
- `status` (toast — good)

Missing: `main`.

**Recommended fix:** Combined with A2-1 — wrap primary content in `<main id="main-content">`.

---

### A2-3: Legend creates 15 individual tab stops in idle

**Severity:** HIGH
**WCAG:** 2.1.1 Keyboard (Level A)
**File scope:** `src/components/Legend.svelte`

**Root cause:** Each of the 15 legend category buttons is a separate Tab stop. In idle state, a keyboard user must Tab through all 15 before reaching the search input, mode chips, or camera controls. This makes the app extremely tedious to navigate.

**Tab order evidence (25 stops mapped):**
```
Tab 1: Skip link
Tab 2: Canvas (role=application)
Tabs 3-17: 15× Legend category buttons (Food & Dining, Professional Services, ...)
Tab 18: Weather toggle
Tab 19: Search input
Tab 20: Legend toggle
Tab 21: Keyboard shortcuts button
Tabs 22-27: 6× Mode chips
Tabs 28-32: 5× Camera controls
Tabs 33-34: Journey buttons
```

**Recommended fix:** Implement roving tabindex on the legend category list. Only the first item (or the active item) should have `tabindex="0"`; all others get `tabindex="-1"`. Arrow keys navigate between items. This collapses 15 tab stops into 1.

**Pattern reference:** WAI-ARIA radiogroup pattern (same as mode chips should use — see A2-5).

---

### A2-4: Mode chips hidden in search/focus modes — keyboard users trapped

**Severity:** HIGH
**WCAG:** 2.1.1 Keyboard (Level A), 2.4.7 Focus Visible (Level AA)
**File scope:** `src/App.svelte`, `src/components/Header.svelte`

**Root cause:** When the user switches to Search or Focus mode, the `#banner` header collapses to `width: 0; height: 0`, hiding the mode chips from keyboard navigation. There are no keyboard shortcuts to switch modes, so keyboard users have no way to return to Overview.

**Evidence:**
```
Search mode: banner computed size = 0×0
Mode chips: not reachable via Tab
Global keyboard shortcuts: Arrow, Home, End, +/- (no mode switch)
Escape key: clears search input, does NOT exit search mode
```

**Recommended fix:**
1. Keep mode chips visible in all modes (at minimum as a compact toolbar)
2. OR add keyboard shortcuts for mode switching (e.g., `Ctrl+1` through `Ctrl+6`)
3. OR ensure Escape exits search/focus mode and returns to Overview

### A2-5: Mode chips use radio semantics but Tab navigation

**Severity:** MEDIUM
**WCAG:** 4.1.2 Name, Role, Value (Level A)
**File scope:** `src/components/ModeChips.svelte`

**Root cause:** Mode chips use `role="radiogroup"` + `role="radio"` + `aria-checked`, which correctly declares radio semantics. However, they're navigated with Tab (one Tab per chip) instead of arrow keys. Per WAI-ARIA, radiogroups should use roving tabindex with arrow keys for intra-group navigation.

**Recommended fix:** Implement arrow key navigation within the radiogroup. Only the active radio should have `tabindex="0"`; others get `tabindex="-1"`. Left/ArrowUp and Right/ArrowDown cycle through options.

---

### A2-6: No H1 heading — heading hierarchy starts at H3

**Severity:** MEDIUM
**WCAG:** 1.3.1 Info and Relationships (Level A)
**File scope:** `src/App.svelte`, `src/index.html`

**Root cause:** The heading hierarchy has no H1. Visible headings are:
- H3 "Categories" (legend)
- H3 "Business Details" (info panel)
- H4 "Status", "Contact", "City" (info panel subsections — hidden in idle)

Screen readers use headings for page structure navigation. Starting at H3 confuses the document outline.

**Recommended fix:** Add a visually hidden H1 at the top of the page content: `<h1 class="sr-only">Semantic Explorer</h1>`. The existing "SE Semantic Explorer" text in the header could be wrapped in this H1.

---

### A2-7: Canvas missing `aria-keyshortcuts`

**Severity:** MEDIUM
**WCAG:** 4.1.2 Name, Role, Value (Level A)
**File scope:** `src/components/Canvas.svelte`

**Root cause:** The canvas `role="application"` element responds to Arrow keys (navigate), Home (reset view), End (recenter), +/- (zoom), but doesn't declare these shortcuts via `aria-keyshortcuts`. Screen reader users don't know what keys are available.

**Current attributes:**
```
role="application"
aria-label="Semantic business visualization of Montgomery County businesses. Use arrow keys to navigate."
tabindex="0"
```

**Missing:** `aria-keyshortcuts="ArrowLeft ArrowRight ArrowUp ArrowDown Home End"`

**Recommended fix:** Add `aria-keyshortcuts` to the canvas element listing all supported keyboard shortcuts.

---

### A2-8: Keyboard shortcuts panel not toggling properly

**Severity:** LOW
**WCAG:** 2.1.1 Keyboard (Level A)
**File scope:** `src/components/Header.svelte` (or related binding)

**Root cause:** The "Open keyboard shortcuts" button exists and has proper `aria-label`, but clicking it doesn't make the panel visible. The panel DOM exists with `visibility: hidden; opacity: 0; aria-hidden: true`.

**Evidence:**
```
Button: <button id="btn-keyboard-help" aria-label="Open keyboard shortcuts">
Panel: <div id="keyboard-hint-panel" role="region" aria-label="Keyboard shortcuts" aria-hidden="true">
Panel computed: visibility=hidden, opacity=0, display=block
After click: no change
```

**Recommended fix:** Debug the toggle logic. The panel should set `aria-hidden="false"` and become visible when the button is clicked. This may be a CSS/JS coordination issue where the toggle class isn't being applied.

6 `aria-live="polite"` regions found — all correctly use `polite` (not `assertive`):

| ID | Component | Purpose |
|---|---|---|
| `info-panel` | InfoPanel | Business details updates |
| `search-status` | SearchResults | Search result count/status |

**Verdict:** Good use of live regions. The `journey-compass` live region may be overannouncing since it contains the full compass UI — consider making only the status text live, not the entire section.
