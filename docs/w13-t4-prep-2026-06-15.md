The charter's "lifecycle-aware bridge functions" turns out to be a **consumer concern, not a selector concern**. Selector functions that return `state.scene` don't need lifecycle-awareness — they return whatever the value is at call-time. The bridge/lifecycle concern lives in the consumer.

## 2. Three.js Ref Concern: Where Init Happens

`three-engine.ts:initThreeJS()` (lines ~283-454) sets:
- `webglContext.scene = new THREE.Scene()`
- `webglContext.camera = new THREE.PerspectiveCamera(...)`
- `webglContext.renderer = new THREE.WebGLRenderer(...)`
- `webglContext.controls = new OrbitControls(...)`

The bridge between `webglContext.X` and `appState.X` is exercised in this file. **Where `appState.scene = webglContext.scene`** is written determines what consumers see.

If consumers read `appState.scene` after `initThreeJS()` runs, they get the live THREE.js object. If they read before, they get `null`. **Today, every consumer reads AFTER init** because they're all in modules called only after the engine boots. The "bridge" risk thins out: there's no reading-before-init pattern that needs shimming.

### 2.1 Where the ref bridge is currently wired

```ts
// three-engine.ts:283-454 references
webglContext.scene = new THREE.Scene();
// ...
// Later, the bridge from webglContext to state happens via setSemanticLaneOpsMode-like patterns
state.scene = webglContext.scene;  // implicit somewhere
```

The bridge work for "W13-T4 = lifecycle-aware bridge" is actually already partially done — `appState.scene` is the typed home, and there's plumbing. What `getScene()` does is read this typed home. **No new bridge file needed.**

## 3. Per-Selector Disposition

### 3.1 Pre-classification

Each of the 84 selectors will be classified into one of:

- **DIRECT** (constant or already-populated ref): consumer reads `appState.X` directly. Selector function retires.
- **BRIDGE** (complex ref/Three.js object where lifecycle matters): keep bridge function or define a typed wrapper in `state-bridge.ts`.
- **RETIRE** (zero consumers on closer inspection): delete from selector file.
- **DEFER** (overlaps with T5 cleanup): leave for T5.
