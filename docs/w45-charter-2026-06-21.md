### What the W44 evidence proves

1. **The script cost is no longer the bottleneck.** TBT is 0 ms everywhere; bootup-time scripting is 70 ms desktop / 316 ms mobile — well within budget.
2. **The first-paint is no longer the network bottleneck.** With fonts same-origin, the largest non-Three.js resources total <350 KB transferred in <1 s on desktop. On mobile (1.6 Mbps sim), network adds ~2 s wall time but is no longer the LCP driver.
3. **The first-paint IS the Three.js scene render itself.** On a 4× CPU throttled mobile, Three.js scene bootstrap (camera, lights, instanced mesh, geometry from typed-array buffer) gates the LCP. W44-P1 deferred the _parse_ but not the _first render_ — deferral alone is provably insufficient.

### Why this is the right next wave (vs "more config tweaks")

| Lever                                                 | Expected LCP delta | Cost                                                          | Verdict                     |
| ----------------------------------------------------- | ------------------ | ------------------------------------------------------------- | --------------------------- |
| Further code-split Three.js internals (~587 KB chunk) | 100–200 ms         | High — invasive refactor across many importers                | Marginal                    |
| Compress CSS bundles (~250 KB total)                  | 100–300 ms         | Low — Vite + terser config                                    | Marginal                    |
| Move all assets to HTTP/2 server push                 | 50–100 ms          | Medium — infra / hosting                                      | Marginal                    |
| **Mobile 2D placeholder + 3D-on-tap**                 | **5,000–8,000 ms** | High — new Svelte component, page-load branch, dynamic-import | **The architectural lever** |

The placeholder approach cuts the LCP measured by Lighthouse (which doesn't tap) from "first 3D frame" to "first paint of static SVG" — a path from 12 s to something well under 4 s. Tap-to-3D preserves the full experience at the cost of one explicit user gesture.

## Goals

### W45-A: Mobile 2D Placeholder — Initial Render

**Impact:** Mobile LCP from 12.1 s toward < 4 s (the meaningful budget tier before 2.5 s Web Vitals "good" threshold). Goal #1: **eliminate the WebGL canvas from the cold-load critical path on narrow viewports.**
**Scope:**

1. **`src/components/Placeholder2D.svelte`** — static SVG preview of the semantic mycelium. Visual contract:
    - Full-viewport (covers the same area the WebGL canvas would)
    - Reuse existing color tokens (`--bg`, `--accent-1..4`)
    - Convey "8,406 businesses, 4 clusters" with cluster-shape silhouettes
    - "Tap to enter 3D scene" affordance, large tap target (≥ 44×44 px)
    - `prefers-reduced-motion`: static, no parallax or pulse
    - SVG raw weight target ≤ 12 KB
2. **Responsive-renderer decision module** — `src/lib/orchestration/responsive-renderer.ts` (new):
    - Owns the _initial-mount kind_ decision: `'webgl' | 'placeholder2d'`
    - Single export `getInitialRenderKind(): 'webgl' | 'placeholder2d'` reading viewport + UA + reduced-motion
    - Mobile-UA detection re-uses existing `isMobileViewport()` from `three-engine.ts` (consolidate into a shared `viewport-utils.ts` if duplication grows)
    - Decision is computed synchronously at module-load (no async dependency on the render path)
3. **App.svelte branch** — at initial mount:
    - WebGL path: identical to today (unchanged)
    - Placeholder path: mount `<Placeholder2D />` instead of `<Canvas />`; **neither WebGL context nor three-engine module is loaded**
4. **Lazy threshold for three-engine**: convert `import './lib/engine/three-engine'` paths in any eagerly-imported chain into dynamic `import()`s behind the placeholder branch. The 587 KB `three-D5X0Mtcg.js` chunk should not enter the network critical path on placeholder initial render.

**Files:** `src/components/Placeholder2D.svelte` (new), `src/lib/orchestration/responsive-renderer.ts` (new), `src/App.svelte`, `src/lib/engine/three-engine.ts` (refactor: hoist `isMobileViewport` to `viewport-utils.ts`)
**Risk:** MED — desktop visual at the viewport boundary (e.g., 768×1024 iPad) must not regress. Specifically: a narrow tablet that historically showed 3D should still show 3D.
**Verification:**

- Playwright cold-load at 375×812 (iPhone X emul) — `<Placeholder2D>` mounts inside `data-render-kind="placeholder2d"`; no `<canvas>` element in DOM
- Playwright cold-load at 1280×720 — `<canvas>` mounts inside `data-render-kind="webgl"`; no placeholder
- `npm run qa:mobile-visual` passes — placeholder screenshot is _visually approved_ against a thumbnail baseline

### W45-B: Tap-to-3D Transition

**Impact:** Mobile users (who would otherwise now see a static preview) get the full WebGL scene with one explicit gesture.
**Scope:**

1. **Tap handler**: clicking the placeholder's "Enter 3D scene" affordance
   a. Sets a transition state (loading screen, 200 ms banner)
   b. Dynamic-imports the three-engine bundle (`import('@lib/engine/three-engine')`) so the 587 KB chunk loads lazily
   c. Calls into the existing `initThreeEngine()` lifecycle path (no new init surface)
   d. On init success: crossfade-out the placeholder; the canvas takes its place
   e. On init failure: surface a "3D scene unavailable — continue in 2D" message
2. **State machine** in `src/lib/state/app.svelte.ts`:
    - Add `renderKind: 'webgl' | 'placeholder2d' | 'transitioning-user' | 'error-3d-unavailable'`
    - The `transitioning-user` state holds the crossfade spinner
3. **Reduced-motion handling**: when `prefers-reduced-motion: reduce`, skip the crossfade — direct swap.

**Files:** `src/components/Placeholder2D.svelte`, `src/lib/state/app.svelte.ts`, `src/lib/engine/three-engine.ts` (no new init surface, reuse `initThreeEngine`/`animate`)
**Risk:** MED — dynamic import path must not pull in already-statically-imported code (the existing `IneffectiveDynamicImport` log lines from W44 build output show this risk). We'll need to verify the three-engine module isn't pulled into any other initial-mount import chain.
**Verification:**

- Playwright: tap triggers dynamic-import of `three-*.js` chunk (network audit shows new `?import=three-D5X0Mtcg.js?t=…` request after tap, _not_ at cold load)
- Playwright: after init, `<canvas>` is in DOM and `render.kind` is `'webgl'`
- Playwright: WebGL fail unit (mocked) — reverts to `'error-3d-unavailable'` with safe state

### W45-C: 2D-Mode Search and Selection (parity safety)

**Impact:** Mobile users in 2D mode still get _the full search-and-focus_ flow, just without 3D. Today the search bar lives in the same always-mounted chrome; this goal confirms that still works.
**Scope:**

1. **Audit** — verify that the search bar, results dropdown, and selected-card InfoPanel paths don't depend on three-engine being mounted. This is mostly a confirmation, but a small migration may be needed if e.g. focus-pocket ripples call into WebGL synchronously.
2. **Fallback for `selected` state**: in 2D mode, the InfoPanel still mounts, but cluster/context visuals (those rendered to canvas) degrade gracefully to a 2D card.
3. **`pointer-events` and `z-index`**: ensure placeholder does not block search bar / InfoPanel interactions.

**Files:** `src/components/SearchBar.svelte`, `src/components/SearchResults.svelte`, `src/components/InfoPanel.svelte`, `src/lib/focus/focus-ui.ts`
**Risk:** LOW — UI chrome is already mobile-aware; this is mostly an audit-and-fix small gaps
**Verification:**

- Playwright mobile cold load → type query → results dropdown appears → tap result → InfoPanel renders correctly with `data-render-kind="placeholder2d"`
