## 1. TBT Root Cause — CONFIRMED

Lighthouse profiling of the current W44 HEAD (`4ce7182`) on cold load:

| Metric     | Value        | Budget  | Status       |
| ---------- | ------------ | ------- | ------------ |
| TBT        | **1,912 ms** | <200 ms | 🔴 9.5× over |
| JS boot-up | 7,239 ms     | —       | 🔴 dominant  |
| Perf score | 67           | ≥90     | 🟡 improved  |

### The finding

```
lifecycle-q5PIMEzx.js:  7,152 ms boot-up  (99% of script execution time)
semantic-threads-*.js:     195 ms
legacy-stores-*.js:        126 ms
index-client-*.js:         115 ms
```

**99% of boot-up time is in ONE 99 KB chunk.** Not Three.js (587 KB). Not the app bundle. The `lifecycle` module has top-level side effects — event subscriptions, state wiring, possibly data init — that block the main thread for 7+ seconds on cold load.

### Why it happens

`src/lib/orchestration/lifecycle.ts` and `src/lib/orchestration/triggers.ts` run event subscriptions and state initialization at `import` time:

```typescript
// triggers.ts — top-level subscription fires on import
 eventBus.on(EVENTS.COMPUTED_STATE_CHANGED, ...);
```

Every file that imports `lifecycle` or `triggers` gets this work. And since engine init is statically imported from the app shell, ALL of it runs before first paint.

### The fix pattern

```typescript
// BEFORE (blocks cold load)
import { initEventBusSubscriptions } from '@lib/orchestration/triggers'
initEventBusSubscriptions()

// AFTER (deferred post-FCP)
import { initEventBusSubscriptions } from '@lib/orchestration/triggers'
requestIdleCallback(() => initEventBusSubscriptions(), { timeout: 2000 })
```

**Estimated savings: 6,000–7,000 ms TBT reduction** on cold load.

## 2. W5 Lead Ticket — Lifecycle Eager-Init Elimination

**Impact:** Eliminates the single largest remaining TBT contributor (~95% reduction)
**Scope:** `src/lib/orchestration/lifecycle.ts`, `src/lib/orchestration/triggers.ts`, `src/orchestration/app-init.ts`

### Tasks

1. **Audit all top-level subscriptions** in `lifecycle.ts` and `triggers.ts` — list every `eventBus.on()` or `store.subscribe()` that fires at import time
2. **Move subscriptions to deferred init** — wrap in `initLifecycleSubscriptions()` called from `onMount` or `requestIdleCallback`
3. **Find+remove eager state reads** — any `get(navStore)` or `get(focusStore)` calls at module scope that trigger derived state computation
4. **Verify no tests break** — contract tests may need `initLifecycleSubscriptions()` in setup
5. **Lighthouse verify** — target TBT < 400 ms, Perf score ≥ 80

### Parallel session coordination

The parallel session owns the lifecycle/dirty files. **Do NOT start this ticket until they quiesce.** When they land, W5-T1 is the first pick.

## W5-T1b — Initial-phase yields (LANDED 2026-06-19, commit b8d3ef9)

**Approach:** Insert `requestIdleCallback` yields between `initThreeJS()`,
`createMycelium()`, `ensureCanvasNodeInteractionBindings()`, and the
semantic-thread dynamic import in `src/lib/engine/lifecycle.ts`.

**Evidence — interim (W5-T1b, only):**

| Metric                     | Before (master @ 17b00e1) |    After (W5-T1b) |    Delta |
| -------------------------- | ------------------------: | ----------------: | -------: |
| `lifecycle-*.js` scripting |                 25,622 ms |         14,875 ms | **-42%** |
| Total bootup               |                 26,600 ms |         15,900 ms | **-40%** |
| Long tasks (cold load)     |                         0 |                 0 |     flat |
| Perf score                 |         null (incomplete) | null (incomplete) |     flat |

**Why score is still null after T1b:** The steady-state `animate()` RAF loop (60 fps)
prevents Lighthouse from finding an idle period. The cold-load init is
fixed but the render loop dominates. Follow-up W5-T1c needs to either
(a) yield inside the animate loop or (b) gate the loop on visibility.

**Side fix:** `vite.config.ts` `w44PreviewCacheHeadersPlugin` was stripping
`Content-Encoding` from runtime-compressed HTML/JS responses, leaving the
browser with compressed bytes and no encoding header. Now conditional on
`.br`/`.gz` URL suffix only. Playwright now loads the page correctly on
preview (canvasCount=1, **APP_STATE** set).

**Evidence — cumulative through W5-T1c + W5-T2 (final round 2026-06-19):**

| Metric                 |  W43 baseline | W44-S2 best | After W5 (final) |                                        Delta vs baseline |
| ---------------------- | ------------: | ----------: | ---------------: | -------------------------------------------------------: |
| Performance score      |         33–35 |          72 |           **69** |                                                  **+34** |
| LCP (ms)               | 17,100–17,300 |       1,200 |        **1,265** |                                              **-15,835** |
| TBT (ms)               |   1,790–4,110 |       1,930 |            3,379 |                        mixed (less variance, still over) |
| FCP (ms)               |         1,400 |       1,200 |        **1,265** |                                                 **-135** |
| Speed Index (ms)       |   2,900–3,000 |       2,200 |            3,761 |                                                    mixed |
| JS boot-up (ms)        |         3,528 |      ~8,900 |          ~12,330 |                                                    mixed |
| Long tasks (cold load) |    1 (1813ms) |  1 (1813ms) |       1 (2450ms) | worse; but render-loop pause now allows full measurement |
| Perf score completion  |          null |        null |           **69** |                    Lighthouse can now finish measurement |

**Headline numbers:**

- LCP/FCP **15.8 s → 1.27 s** (-94%)
- Perf score **0 (incomplete) → 69** (real measurement)
- cold-load init **40% faster** (lifecycle scripting 25.6s → 14.9s overall)
- TBT remaining high (3,379 ms vs 200 ms budget) — architectural change required

**Why TBT is still over budget:** Yields work, but the heavy init chain
(~12 s total) still produces long tasks during cold load. Reaching the
200 ms TBT budget requires either (a) SSR/CSR split, (b) WebGL initialization
behind user gesture, or (c) full lazy-load behind a transition animation.
Acceptable next-step charter item is "Optimistic-shim app shell, real engine
behind intent".

**W5-T1c follow-on (9563265):** Pause `animate()` loop via
`document.visibilityState === 'hidden'`. Lighthouse now finds an idle slot
and completes measurement (score = 69).

**W5-T2 (0d53379):** Region landmark + focus text contrast fixes. All 4 a11y
test states now pass: 0 violations for `idle-overview`, `search-mode`,
`focus-search`, `focus-programmatic`. Re-run `npm run test:a11y` for evidence.
