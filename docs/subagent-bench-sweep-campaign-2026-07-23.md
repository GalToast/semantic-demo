## Lesson learned (sweep dispatch playbook)

1. **Always verify file-write via stat, never trust `status:completed` + textual `DONE:` reply.** L4 att1 + L4 att2 + L3 att3 all streamed a `DONE: <path>` text reply without ever emitting any `write` tool_call. The benchmark-parent rule bears repeating: a worker reporting `status:completed, exit_code:0` with `output_state:assistant_output_seen` may have hallucinated completion. Grep worker stdout.log for `"toolName":"write"` or `"Successfully wrote"` to confirm — stat the report path on disk after every completion.
2. **For OpenCode Zen route launches, pin to `deepseek-v4-flash-free` as the FIRST attempt.** It produced actual file writes on 5/5 dispatches today (L1 att2, L2 att1, L4 att3, L5 att4, L6 att1). `north-mini-code-free` should NOT be used as the primary sweep writer — 3/4 dispatches hallucinated "DONE:" text without emitting `write`. Skip `mimo-v2.5-free`, `nemotron-3-ultra-free`, `nemotron-3-super-free`, `qwen3.6-plus-free`, `qwen3.6-35b-a3b` entirely for sweep-style work — all proven unstable or rejected upstream today.
3. **Stale-launcher-allowlist detection (within ~2 s of dispatch):** When the launcher allowlist contains a model the upstream rejects, the worker reports `stop_reason:error` + `errorMessage:"401: ModelError"` synchronously with `stdout_bytes ≈ 18000`. Detect via `live.stream_summary.stop_reason === "error"` + `live.stream_summary.errorMessage` in the poll response. Do NOT wait — re-dispatch immediately on a different endpoint.
4. **Stale-PID-death-by-LSP-wedge (NEW — observed L3 att4):** A worker can produce 15 `write` tool calls (all to helper scripts) and 937 bash calls then go quiet for 11+ minutes if `pi-lens-shared-lsp` daemon cold-start crashes (`Daemon exited with code: 1`). Detect via `pid_alive:false` + `status:stale` + `last_log_at` more than ~5 minutes behind `quiet_for_seconds`. The bash auto-detach threshold (15 s) + LSP-daemon wedge is the spawning-layer #2 wedge from the spawn-wedge skill — it is NOT a model-endpoint wedge. Recovery: re-dispatch with fresh cold-start (cheaper than `external_subagent_followup`, which inherits the dead-LSP-context session).
5. **Worker prompt must explicitly demand the `write` tool call** as the LAST step — not just "the report file at: path" — for the `north-mini-code-free` model in particular, since textual-DONE-without-write is a reproducible pattern (L3 att3 + L4 att1+att2 all replicated). The current prompts already do this and the hallucinations still occurred — model behavior depends on the model, not the prompt strength. Mitigation: use `deepseek-v4-flash-free` from the start.
